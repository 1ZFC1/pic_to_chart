# pic_to_chart：把图片转成 Rizline 谱面

用 [`rizChartFunction`](../rizChartFunction_Library) 把一张图片“画”进 Rizline 编辑器：
图片被采样成一条条**引导线**（linePoints），在编辑器里随播放头推进、按拍滚动显示。

本目录只依赖 `../rizChartFunction_Library`（谱面读写 / 节点创建 / 校验导出）和
常规定量图像库（Pillow、numpy、scikit-image）。坐标换算的依据见
[`EDITOR_AXES_REFERENCE.md`](EDITOR_AXES_REFERENCE.md)。

## 1. 它做了什么

1. 读图片（PNG/JPG/BMP…，自动转 RGBA，可限制边长）；
2. 按 `scan`（逐行扫描）、`outline`（轮廓描边）或 `thin`（骨架中心线）
   把图片变成一堆折线，每个顶点带一个 RGBA 颜色；
3. 用 `rizChartFunction` 建谱面：`new()` → 每条折线一条 `addLine()`，
   判定环颜色节点统一全透明；
4. `check()` + `export()` 严格校验后写出 JSON；
5. 可选把整张谱面按世界坐标渲染成 PNG（`--preview` / `--compare`），
   先看效果再进编辑器。

生成的谱面**只有引导线，没有 Note**，可以直接在编辑器里看，也可以
`--chart 已有谱面.json` 追加到现有谱面里（沿用它的 BPM/画布，**默认接在现有画布
之后**、不覆盖原内容；谱面里的 `__db` 工坊元数据会原样保留）。

## 2. 环境与安装

- Python **3.10+**；本机用 `python` 即可。
- 依赖：`Pillow`、`numpy`、`scikit-image`（`outline` 模式才需要后两个里的
  skimage，`scan` 模式也用到 numpy）；**图形界面**另需 `PyQt5`。
- 谱面库：克隆到 `工具/rizChartFunction_Library`（本工具的上一级目录），
  或用环境变量指定 src：

```powershell
git clone https://github.com/xp00000002/rizChartFunction_Library
python -m pip install Pillow numpy scikit-image

# 如果库不在默认位置：
$env:RIZCHARTFUNCTION_SRC = "D:\path\to\rizChartFunction_Library\src"
```

工具会自动在以下位置找 `rizChartFunction/src`：环境变量 →
`工具/rizChartFunction_Library/src` → 上两级目录 → 当前目录。

## 4. 原理：像素怎么变成 xPosition 和 tick

### 4.1 坐标事实（参考文档 + 本机实测）

| 事实 | 数值 | 来源 |
| --- | --- | --- |
| 世界 x / xPosition | **5.625** | 同一画布两个已渲染线节点反解 |
| 世界 y / 秒（V） | **6.4**（实测 6.37–6.38） | 红框 + 方括号两处截图反解 |
| 1 秒 / tick | `60 / BPM` | BPM 时间轴 |
| 基础横向格距 | 世界 0.5625 = 局部 0.1 | 吸附网格实测 |
| 一屏横向宽 | **1.0** xPosition 单位（世界 5.57） | 截图：1 单位宽的红框正好铺满可见区 |
| 一屏世界高 | **6.9** 世界单位（≈3.17 拍 @175BPM） | 截图：可见区 679px ÷ 98px/世界 |
| 开始淡出 | \|x\| ≈ **0.4** | 参考文档 + 截图 |
| 完全不可见 | \|x\| ≈ **0.5**（可见区左右边缘） | 同上 |

> **可见区是“竖长”的**：宽 5.57、高 6.93 世界（宽高比 ≈0.80），不是 16:9。
> Rizline 是竖屏游戏，编辑器露出的就是竖版 playfield。这一点和“一屏 1.0 个单位宽”
> 一起，把早先按 16:9 推算的 2.8 单位宽彻底推翻了。

实测依据（BPM 175 的标定谱面 + 编辑器截图逐像素量）：

| 参照物 | 谱面里的尺寸 | 截图（px） | 换算成世界 |
| --- | --- | --- | --- |
| 绿色方括号 | 0.72 x 单位 × 3.05 tick | 397 × 653 | 4.05 × 6.66 |
| 白色可见框 | — | 546 × 679 | **5.57 × 6.93** |

用方括号的**宽度**定标得 98.0 px/世界，再拿它的**高度**反解出每 tick 2.184 世界
→ **S1 = 6.37**；而红框（1 tick）在上一张截图里量到 2.19 世界 → **S1 = 6.38**。
两个独立来源一致，和下面 4.1.1 的官方公式（S0=1.5 → 6.389）也一致。

> 参考文档里“`abs(xPosition)` 0.4 开始淡出、0.5 完全不可见”在 xPosition 单位下
> 就是字面意思，和“1 单位宽的红框正好铺满可见区”完全一致。

### 4.1.1 流速与一屏拍数（官方公式已对上）

编辑器“设置”里的**播放流速 S0** 不是游戏里真正的流速，两者关系（摄像机缩放 = 1）：

```text
S1 = 7 × (S0 − 1) / 9 + 6            # 例如 S0=1.5 → S1=6.389
世界纵向坐标 y = S1 × floorPosition  # floorPosition = ∫画布流速 d(秒)
每拍世界高度   = S1 × (60 / BPM) × 画布流速
一屏拍数 x     = H ÷ 每拍世界高度 = H × BPM / (60 × S1)     # H ≈ 6.9
```

`x ∝ BPM` 这一点不变；对流速则是**线性反比**（S1 越大窗口越小），而不是之前猜的
“几乎无影响”。三个旧读数正好印证：它们比公式预测恒定多出约 +0.8 根（数白线时
把半拍彩线/边缘线算进去了）：

| S0 播放流速 | S1 真实流速 | 公式预测一屏拍数 | 早先读数 | 差 |
| --- | --- | --- | --- | --- |
| 1.5 | 6.389 | 3.15 | 4.0 | +0.85 |
| 3.0 | 7.556 | 2.66 | 3.4 | +0.74 |
| 5.5 | 9.500 | 2.12 | 3.0 | +0.88 |

工具里 `--flow` 就是 S0，`--speed-const` 直接给 S1（两者等价，`--flow` 优先）。

| BPM（H=6.9, S1=6.389） | 一屏拍数 = 6.9 × BPM / (60 × 6.389) |
| --- | --- |
| 120 | 2.16 |
| 175 | 3.15 |
| 220 | 3.96 |
| 350 | 6.30 |

换歌只要改 `--bpm`（或用 `--chart` 沿用谱面 BPM），窗口会自动跟着变；
换流速就改 `--flow`（GUI 里是“播放流速”）。

### 4.2 本工具的映射

图片像素 → 谱面，是两个轴同比例的仿射映射：

```text
dx       = width_x / 图片宽度(px)          # 每个像素多少 xPosition
aspect   = 5.625 × BPM / (60 × speed_const) # 1 个 x 单位 = 多少 tick
dy       = dx × aspect                      # 每个像素多少 tick

x(px)     = center_x + (px - 宽/2) × dx
tick(row) = start_beat + (高 - row) × dy    # row=0 是图片顶部，所以顶部 tick 更大
```

于是图片不会被拉长或压扁：横向 1 像素和纵向 1 像素在谱面里等长。

`aspect` 也可以直接给：`--aspect 2.52`（单位 tick / x 单位）。默认按 BPM 现算，
因为编辑器纵向是按**秒**走的，BPM 变了同样的 tick 高度就变了。

**和库里 `timemultiple=1.65` 的关系**：`drawPolygon/drawEllipse/drawText` 的默认
`timemultiple=1.65` 是库作者在“谱面流速 6.5、画布流速 1”下量出的单点经验值，
相当于 BPM≈114 时的 `aspect`。本工具按 BPM 现算（175 BPM ≈ 2.52），所以同一个
BPM 下不要同时套用 1.65，否则图形会被压扁。

### 4.3 为什么是“滚动揭幕”

引导线的纵向位置由时间决定（`floorPosition × 流速`），所以整张图不会同时出现：
播放头附近的那一条横带才在屏幕上。图片越高，需要越长时间才能看完整。工具会把
总高度换算成“多少 tick / 多少秒 / 约几屏高”打印出来。

节点高度（`floorPosition`）全部由库按 BPM/画布流速算，**不要手写**；本工具只给
`time / xPosition / color`。

## 5. 四种模式与参数

### 5.1 `scan`：逐行扫描（默认）

把图片重采样成 `cols × rows` 的网格；每一行里连续的可见像素拼成一条**水平**
引导线，节点颜色就是像素颜色。适合照片、插画、渐变、多色图。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--cols` | 0（自动） | 横向采样列数；0 = 按图片宽高比推 |
| `--rows` | 0（自动） | 纵向采样行数；0 = **让行距等于 `--line-width`**（线条首尾相接，无横条纹） |
| `--color-tolerance` | 8 | 颜色足够接近时丢掉中间节点（0 = 全部保留） |
| `--alpha-cut` | 8 | alpha 低于该值当透明 |
| `--whole-row` | 关 | 每行只出一条整行线，空隙用 alpha=0 节点（线少、节点多） |

**条纹问题**：行与行之间的空白取决于“行距（世界单位）”和编辑器真实线宽。默认
行距就是 `--line-width`，所以一般是连续的。实测编辑器线宽约 **0.04** 世界单位
（标定橙色梯：0.04 刚好贴合、0.02 / 0.03 糊成一条、0.05 还有缝），工具默认就按
这个值走；如果你的编辑器/缩放不同，按量到的值传 `--line-width`，行数会自动跟着变。

### 5.2 `column`：逐列扫描

`scan` 的转置：每一**列**里连续的可见像素拼成一条**竖线**（x 固定、tick 从下往上）。
参数与 `scan` 相同（`--cols` / `--rows` / `--color-tolerance` / `--alpha-cut`）。

列距按编辑器的**水平细分**取：实测水平细分到 **1/16** 时，相邻两条竖线恰好紧贴——
基础格距 0.1 个 xPosition 单位 ÷ 16 = **0.00625** 个 xPosition 单位（≈0.035 世界），
和 0.04 的线宽基本相等。所以一屏宽（1.0 单位）会自动排 **160 列**：

```text
列数 = 图片宽度(x) ÷ 0.00625        → 1.0 单位 = 160 列
行数 = 列数 × 图片高宽比            （沿时间方向的采样密度，只影响颜色过渡）
```

想更密/更疏就手动给 `--cols`（列距 = 宽度/列数）；竖着出现条纹时说明列距超过了线宽，
加大 `--cols` 即可（工具也会在摘要里提示）。

### 5.3 `outline`：轮廓描边

先做掩膜（有透明通道按 alpha，否则按亮度 Otsu 自动阈值），再用 marching squares
提轮廓，按“行单调”切段（`addLine()` 会按 time 排序，非单调轮廓会被连错），
每段一条引导线。适合线稿、logo、纯色剪影、透明底贴图。

**被画框截断的部分保持断开**：轮廓贴到图像边界时，marching squares 给的是开放路径，
工具就让它开放地画出去（象是被画框切掉的衣服/头发那样），不会把首尾硬连起来。
否则会沿边界补出一条横跨画面的假线：



| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--ink` | 自动 | 亮度阈值：比它暗的算墨迹；不给则透明图按 alpha、不透明图按 Otsu |
| `--invert` | 关 | 反相：亮的算墨迹（黑底白字） |
| `--tolerance` | 1.0 | 轮廓简化容差（像素），越大节点越少、拐角越方 |
| `--smooth` | 0（关） | **轮廓平滑强度（像素 σ）**，消像素阶梯/小噪点，角点会保住 |
| `--layers` | 1 | 描边层数，>1 时向外扩张、视觉加粗 |
| `--layer-gap` | 2 | 每层向外扩多少像素 |
| `--min-length` | 4.0 | 短于该长度（像素）的轮廓丢弃 |
| `--color` | 取色 | 固定描边色（如 `#FF3355`）；默认从墨迹里取平均色 |

**`--smooth`：轮廓平滑**（默认关，推荐 1.0～1.5）

低分辨率图、视频抽帧的斜边上一定有一层 1 像素阶梯，直接描出来会有细碎抖动和小噪点。
打开后流程变成：

```text
掩膜 → 高斯(σ) → 0.5 等值线（亚像素、无阶梯）
     → 保角点的 Chaikin 平滑（转角 > 60° 的点钉住不动）
     → Douglas-Peucker 简化
```

从左到右：原图、`--smooth 0`、`1.0`、`2.0`（下面的数字依次是 150 线/640 节点、
134/509、92/407）：



- **σ=1.0**：去掉噪点、边更顺，节点约 -20%，小细节（字里的小点）还在；
- **σ=2.0**：更干净、节点约 -35%，但 2～3 像素的小结构会被抹掉；
- **角点保护**：直角仍然是直角（实测角点偏差 < 0.5 px）；
- 代价：轮廓可能整体外扩/内缩半个像素；细笔画有时会被切成更多段。

### 5.4 `thin`：骨架中心线

同样先做掩膜，然后 `skimage.morphology.skeletonize()` 细化成 1 像素骨架，再把
骨架像素走成一条条路径（端点/分叉处断开），按行单调切段。适合真正“一笔一画”
的线稿：一条笔画只出一条引导线，不会像 `outline` 那样内外各一条。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--simplify` | 0.8 | 骨架简化容差（像素），越大越“直”、细节越少 |
| `--min-length` | 4.0 | 短于该长度（像素）的骨架分支丢弃（同时能去掉毛刺） |
| `--ink` / `--invert` / `--color` | 同上 | 与 `outline` 相同 |

粗笔画细化后是一条中心线，所以“粗细”信息会丢失——需要加粗时用
`outline --layers`，或者把线宽交给编辑器。

### 5.5 位置参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--start-beat` | 8.0 | 图片**底部**所在的拍；整张图向上展开 |
| `--width-x` | 0（自动） | 图片横向宽度（xPosition）；0 = 用 `--max-width-x` |
| `--max-width-x` | 1.0 | 自动宽度上限，1.0 刚好一屏宽 |
| `--screens` | 0（关） | 让图片竖着正好占 N 屏高（1 = 一屏看全，2 = 滚两屏） |
| `--fit-screen` | 关 | 等价于 `--screens 1` |
| `--flow` | 0（关） | 编辑器里的播放流速（默认等价 1.5）；按实测曲线换算 V |
| `--visible-ticks` | 0（自动） | **一屏能看到多少拍**（标定量出来的）；>0 时优先用它 |
| `--view-height` | 6.9 | 一屏对应的世界高度（100% 缩放时） |
| `--zoom` | 1.0 | 编辑器整体缩放倍数（100% = 1.0），可见范围按 1/zoom 变化 |
| `--center-x` | 0 | 横向中心；和 `--width-x` 一起摆位置 |
| `--aspect` | 0（自动） | 1 个 x 单位 = 多少 tick |
| `--speed-const` | 6.389 | 真实流速 S1（世界单位/秒）；直接控制图形比例 |
| `--canvas` | 0（新建）/ 自动（追加） | **写到哪个画布**（canvasIndex，负数从末尾数）；`--chart` 追加时默认接在现有画布之后 |

**画布（`--canvas`）**：线节点写进这个画布。可能报错/需要注意的情况：

- 新谱面只有画布 `0`；要给 `1`、`2`… 会自动补齐（`addCanvas()` 追加，默认 x=0、流速 1），
  摘要里会提示“已自动新增 N 个画布”；
- **追加到已有谱面时，不给 `--canvas` 就自动接在现有画布之后**（原内容不动）；
  显式给 `--canvas 0` 才会写进 0 号画布、和原内容重叠；
- 写进**不存在**的编号会被自动补齐，但补出来的新画布位置/流速是默认值，
  画面上可能对不上；
- 负数按“从末尾数”解析，超出范围（例如只有 2 个画布却给 `-5`）直接报错；
- 画布索引只影响**写在哪**，不影响坐标换算（`xPosition` 始终是画布局部坐标）。

`--flow` / `--speed-const` / `--aspect` 三个只影响**图形比例**；`--screens` /
`--visible-ticks` / `--view-height` 只影响**图有多大、滚几屏**。两组互不干扰，
标定时分开量即可。

## 6. 预览与自检

```powershell
python pic_to_chart.py 图片.png -o chart.json --preview chart.png --compare cmp.png
```

- `--preview`：按世界坐标渲染整张图（`X = (xPosition+画布x)×5.625`，
  `Y = floorPosition×speed_const`），并按线条平均亮度自动选底色（深色线用白底）；
- `--compare`：左原图、右谱面渲染，一眼看比例对不对；
- `--show-screens`：预览里每隔“一屏”画一条灰线，直接看出这张图要滚几屏；
- `--bg`：手动指定预览底色（如 `#101010`）；
- `--line-width`：引导线视觉线宽（世界单位），默认 **0.04**（实测值）；预览粗细和
  scan 模式的自动行距都用它；
- `--preview-width`：预览最大宽度（像素）。

预览用的是**世界坐标**，所以它和编辑器里看到的比例是一致的（前提是
`--speed-const` 与你的编辑器流速一致）。它不模拟淡出、判定线、镜头缩放。

## 7. 在编辑器里使用

1. 把生成的 JSON 放进你的谱面目录，或直接用编辑器打开；
2. 跳转到 `--start-beat` 前后，按播放，图片会自下往上“揭幕”；
3. 判定环颜色节点是全透明的（和库里 `drawPolygon/drawText` 的做法一致），
   所以画面上不会出现判定圈；
4. 想和现有谱面合体：`--chart 已有.json -o 输出.json`，生成的线会追加在末尾，
   并沿用原谱面的 BPM（`--start-beat` 是绝对拍，注意别和已有内容重叠）；
5. 生成的谱面没有 Note；要变成可玩的谱面，在编辑器里继续加 Note，或把这段
   作为“线画演出”并入现有谱面。

注意事项：

- **宽度别超过一屏**（默认 1.0）。超出的部分在编辑器里会淡出/看不见；
- **节点数量**是主要性能开销：`scan` 模式 1 万节点以内很稳，接近 3 万要谨慎；
  觉得卡就调小 `--cols/--rows`、调大 `--color-tolerance`，或改用 `outline`；
- 想放在音乐的高潮处，就把 `--start-beat` 设到那一段的起点；
- 编辑器里改完记得另存，避免覆盖工具输出。

## 8. 标定：把比例、一屏拍数、线宽量准（已完成，参数已定稿）

> **本机已经标定完毕，下面这些值就是默认值，日常转图不用再标定：**
>
> | 量 | 定稿值 | 怎么来的 |
> | --- | --- | --- |
> | 一屏宽 | **1.0** 个 xPosition 单位 | 截图：1 单位宽的红框正好铺满可见区 |
> | 一屏高 | **6.9** 世界单位（≈3.15 拍 @175BPM、S0=1.5） | 截图逐像素：546 × 679 px ÷ 98 px/世界 |
> | 纵向常数 | **S1**（S0=1.5 时 6.389） | 官方公式 S1=7(S0−1)/9+6，与截图反解 6.37–6.38 吻合 |
> | 淡出 | \|x\| 0.4 → 0.5 | 参考文档 + 截图 |
> | 线宽 | **0.04** 世界单位 | 橙色线宽梯：0.04 刚好贴合 |
> | 播放流速 | **无影响** | 1.5 与 5.5 都是一屏约 3.1 拍 |
> | 复核 | 绿色方括号**基本贴合**上下边缘（<1%） | 回归编辑器实测 |
>
> 只有换窗口大小 / 改整体缩放（`--zoom`）时才需要重新量一次。

如果将来要重新标定：

```powershell
python pic_to_chart.py --calibrate calibrate.json --preview calibrate.png
```

在编辑器里打开标定谱面，从下往上会看到：

1. **红框**：数值上 1 x 单位宽、1 tick 高——一个“参照物”；
2. **绿框**：1 x 单位宽、`aspect` tick 高——按工具换算它才是正方形；
3. **蓝圆**：半径 0.5 x 单位，按换算画出，应该是正圆；
4. **白色横向刻度**：x = -1.8 … 1.8（0.5 长刻度 + 0.1 短刻度）——数一屏实际能放
   几个 x 单位，也能看出淡出从哪里开始（实测 ±1 清晰、±1.5 已消失）；
5. **纵向刻度**：每 0.5 拍一根线，**整拍是白线**、半拍是彩色线，共 20 拍——
   数一屏里能看到几根**白线**，就是一屏多少拍 `x`；
6. **橙色线宽梯**：一对对间距从 0.02 到 0.20 世界单位的水平线，从“明显分开”
   到“糊成一条”的那个间距，就约等于编辑器的真实线宽（实测 0.04）；
7. **浅绿色方括号**：上下两条横线相距 = 工具预测的**一屏高度**。它应该正好顶到
   屏幕上下边缘；只占屏幕一半，就说明实际一屏是预测的两倍——把 `--visible-ticks`
   或 `--view-height` 按这个比例改掉即可（比例参数不用动）。

对不上时怎么调：

| 看到的现象 | 改什么 |
| --- | --- |
| 绿框/蓝圆偏扁（横向被拉长） | `--aspect` 调大（或 `--speed-const` 调小） |
| 绿框/蓝圆偏瘦高 | `--aspect` 调小（或 `--speed-const` 调大） |
| 一屏放不下 1.0 个 x 单位 | 用 `--width-x` 按刻度实际值改小 |
| 预览比编辑器细/粗 | 把量到的线宽填给 `--line-width`（行数会自动跟着变） |

当前默认参数就是实测值：175 BPM 的一屏 = **1.0 单位宽 × 6.9 世界高 ≈ 3.15 拍**
（绿色方括号 + 红框标尺在编辑器截图里逐像素量出来的，误差 <1%）。

想验证“一屏拍数 ∝ BPM”，再生成一份 BPM 翻倍的标定谱面，白线数应该正好翻倍：

```powershell
python pic_to_chart.py --bpm 350 --calibrate cal350.json --preview cal350.png
```

量完之后这样用（两组参数各管一件事）：

```powershell
python pic_to_chart.py 图.png --flow 1.5 --screens 1 `
    --preview p.png --compare c.png --show-screens
```

- `--flow`（或直接 `--speed-const` / `--aspect`）：决定**图形比例**（绿框是否正方形）；
- `--visible-ticks`：一屏几拍（数白线得来）。**只影响“图有多大/要滚几屏”**，
  量错了不会把图拉变形，只会让它偏大或偏小；不给就按 `--flow` 的曲线推算；
- `--screens N`：让图片竖着正好占 N 屏高（`--fit-screen` 等于 `--screens 1`），
  比手算 `--width-x` 直观；`--show-screens` 会在预览里画出每屏的分界灰线。

标定一次之后，同一 BPM、同一流速下都可以沿用这组参数。

## 9. 常见问题

**Q：生成的图在编辑器里是横条纹 / 看不清**
行距大于真实线宽。默认行距就等于 `--line-width`，把标定量到的真实线宽填进去即可。

**Q：图片被压扁了 / 变高了**
比例只跟 `--aspect`（以及 `--speed-const`、`--flow`、BPM）有关。用 `--flow` 填
编辑器里的流速，或直接用 `--visible-ticks` 只调大小。

**Q：图片超出屏幕，两边/上下看不见**
- 上下：用 `--screens 1` 让整张图一屏看全，或 `--visible-ticks` 填实测拍数；
  接受“边播边看”就把 `--screens` 设成 2、3；
- 左右：一屏宽约 1.0 个 x 单位，超过就调小 `--width-x`（`--max-width-x` 默认 1.0）。

**Q：双击 `图片转谱面_GUI.bat` 只弹一下黑框、没有界面**
那是启动期崩了。脚本会把异常写到 `gui_error.log`（就在 `pic_to_chart` 目录），
并弹一个 Windows 消息框告诉你。也可以直接用命令行跑一次看报错：

```powershell
python pic_to_chart_gui.py
```

最常见的原因是没装 PyQt5（`python -m pip install PyQt5`），或者 `pythonw`
指向了另一个没装依赖的解释器——用 `where pythonw` / `where python` 看一眼是不是同一个。

**Q：`outline` 什么都没画出来**
掩膜是空的。白底黑线稿加 `--ink 128`；黑底白线稿加 `--ink 128 --invert`；
透明图检查 `--alpha-cut` 是否过高。

**Q：节点太多、编辑器卡**
`--color-tolerance 12`、`--tolerance 1.5`、`--cols 96`，或 `--mode outline` / `--mode thin`。

**Q：想放进已有谱面**
`--chart 已有.json`，并用 `--start-beat` 选一段空拍。

**Q：线稿被画成了两条边**
`outline` 是沿掩膜边界描边，细笔画会有内外两条。想要单线用 `--mode thin`。

## 11. 已知限制

- **可见窗口 = 1.0 单位宽 × 6.9 世界高**，来自 175 BPM 的截图逐像素测量（误差 <1%）；
  窗口大小、整体缩放（`--zoom`）变化后要重新量（绿色方括号 + 红框标尺）。
- **播放流速会改变窗口**：`S1 = 7(S0−1)/9 + 6`，S0 越大一屏拍数越少（S0=1.5 → 3.15 拍、
  S0=5.5 → 2.12 拍）；要单独改窗口大小用 `--visible-ticks` / `--zoom`。
- 一屏拍数 ∝ BPM 的关系是模型推出来的（H 固定、每拍世界高度 ∝ 1/BPM）。换一首
  歌只需改 `--bpm`（或 `--chart` 沿用谱面 BPM），窗口会自动跟着变。
- **S1 = 7·(S0−1)/9 + 6** 是官方给定的换算（摄像机缩放 1），三处截图测量（6.37 /
  6.38）与它（6.389）吻合；`--flow` 填 S0、`--speed-const` 填 S1。
- 改**摄像机缩放**时可见范围按 1/zoom 变化，用 `--zoom`；改**流速**用 `--flow`。
- **预览不模拟淡出、判定线和镜头缩放**，也不模拟线条的抗锯齿和粗细过渡。
- **图片是“滚动揭幕”**，不是静态贴图；想要静态感就用 `--screens 1`。
- `outline` 对细线稿会画出内外两条边，“粗细”是保留的；`thin` 只出中心线、丢粗细。
  两者按需选；`--layers` 只给 `outline` 加粗。
- 生成谱面只含引导线，不含 Note、Riztime、主题配色；这些在编辑器里继续做。
